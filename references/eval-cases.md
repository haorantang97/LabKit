# Open Loops 回归用例

仅在修改、测试或发布 Skill 时读取。生产审查员不要读取本文件。

## 目录

1. 测试方法
2. 历史核心用例
3. 跨场景用例
4. 验收标准

## 1. 测试方法

- 每次从原始 fixture 重建隔离副本，不能沿用上次审查后的状态卡。
- 使用新的独立审查员；只给 Skill、原文文件和状态卡路径。
- 不在提示词中写预期条目、历史错误或修复方向。
- 同一核心用例至少独立运行五次，比较最终卡片，不只比较聊天回报。
- 记录漏检、误报、父子重复、拆分过细、虚构代决和错误核销。

## 2. 历史核心用例

### A. 长答案中的局部回应

助手最后给出五项建议；用户明确接住第 1、4、5 项。前文还有大量表格、解释和技术细节。

预期：只登记第 2、3 项。前文被最终清单覆盖；不得逐行登记图表，不得拆分一个编号项。

### B. 旧账核销

状态卡有六条旧账。助手后来完整回答交互方案和防滥用调研，只给一套可视化推荐而非用户要求的多个方案；
用户用“继续”接住紧邻的下一版组合。

预期：保留“多个可视化方案仍缺”、语义代决、颜色范围代决；关闭交互方案、防滥用调研和下一版组合；
不从状态汇报、技术实现或直接信息答案中新增条目。

### C. 首次检测

用户提出多项执行要求和三项回答要求；助手明确点名承接执行要求，但只承诺稍后交付方案、交互解法与
调研答案，并自行解释一个歧义词和颜色覆盖范围。

预期：登记三个未实质回答的请求和两个有原文替代分支的代决。代码复用、组件组织和普通实现方向不登记。

### D. 整组确认

助手给五个同级知识结论，用户明确说五点及限定条件全部接受。

预期：`NONE`，卡片未闭环为零。

## 3. 跨场景用例

### 研究或学习

助手给五个编号知识点，用户只回应其中三点。

预期：只登记遗漏的两个同级知识点；引用、论文链接和例子不登记。

### 写作或创意反馈

助手给四个顶层问题，每个问题带例句。用户只接住两个问题。

预期：登记另两个顶层问题，不登记例句。

### 父子覆盖

用户接受一个完整驾驶舱方案，没有逐项复述方案中的图表行。

预期：普通图表行随父项闭环；只有明确标成独立选择或重大例外的子项可以继续挂。

### 真实代决

助手把用户原词 A 解释为 B，原文同时保留 A/B 两个分支，用户未回应。

预期：登记一条代决，并引用两个分支。

### 伪代决

助手在授权范围内复用代码、建立组件、测试、提交或推送；原文没有要求用户在其他路径间选择。

预期：不登记，不得为了满足格式创造替代项。

### 请求完整性

用户要求三个方案，助手只给一个推荐组合。

预期：请求缺口继续挂，并把理由更新为“仍缺多个可比较方案”。

### 维护隔离

用户只讨论 Open Loops 的状态、规则、误报、测试或发布。

预期：两个业务文件字节级不变。

## 4. 验收标准

核心历史用例每个运行五次：

- A 必须 5/5 精确只返回两个目标项。
- B 必须 5/5 精确完成三保留、三关闭且无新增。
- C 必须 5/5 精确返回五项，不得出现机械实施代决。
- D 必须 5/5 返回 `NONE`。

完整测试集要求：

- 历史核心精确匹配率 100%。
- 跨场景精确匹配率至少 95%。
- 目标漏检为零。
- 父子重复为零。
- 虚构替代项为零。
- 维护通道污染为零。
- 状态卡未闭环区只使用阿拉伯数字有序列表，不出现标签或重复编号。
- 更新轮次必须等于原文最后一个用户轮次。

未达到门槛时不要发布为稳定版本；先修改协议，再从原始 fixture 全量重跑。
